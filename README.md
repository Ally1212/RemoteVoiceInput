# 远程语音输入（RemoteVoiceInput）

在本机用豆包输入法说话，把识别出的文字粘贴到苹果“屏幕共享”里的远程 Mac。无需在远程电脑安装软件。

**本机听写 → 本机输入窗 → 共享剪贴板 → 远程粘贴**

工具本身不录音、不识别语音、不传输麦克风；语音识别由你使用的输入法完成。也可以直接键入或粘贴文字。

## 下载与安装

版本更新内容见 [更新日志](CHANGELOG.md)。

1. 打开 [Releases](https://github.com/Ally1212/RemoteVoiceInput/releases)，下载最新的 `RemoteVoiceInput-macOS-arm64.zip`。
2. 解压后，将“远程语音输入”拖入“应用程序”，双击打开。
3. 本版本适用于 **Apple Silicon Mac（M 系列芯片）、macOS 13 或更新版本**。Intel Mac 可尝试从源码自行构建。

发布包采用 ad-hoc 签名，**未经过 Apple 公证**。首次打开时，macOS 可能阻止运行；确认来源后，可在“系统设置 → 隐私与安全性”中找到相应提示并选择“仍要打开”，然后按系统提示操作。系统版本不同，提示文字可能不同。

应用是菜单栏工具，启动后没有 Dock 图标；请在屏幕顶部菜单栏寻找对话气泡图标。

## 首次设置

1. 在本机安装并设置好豆包输入法，确认它可以在普通文本框中语音输入。
2. 打开 macOS 自带的“屏幕共享”，连接远程 Mac。在“编辑”菜单勾选 **“使用共享的剪贴板”**。
3. 打开远程语音输入。如果输入窗或菜单显示辅助功能尚未授权，点击“开启辅助功能”，在系统设置中允许“远程语音输入”。回到工具后应显示 **“辅助功能已授权 ✓”**。
4. 首次发送时，macOS 可能询问是否允许本工具控制 **System Events（系统事件）**；请允许。这个自动化权限用于发送一次粘贴快捷键，与辅助功能权限是两项独立授权。可在“系统设置 → 隐私与安全性 → 自动化”中检查。

## 每次使用

1. 在屏幕共享窗口中，点击远程 Mac 上要输入文字的文本框。首次测试建议使用远程“文本编辑”的空白文档。
2. 按 **`⌘L`** 打开本机输入窗，也可以点屏幕共享窗口右上方的“语音输入”悬浮按钮。
3. 用豆包平时的语音快捷键说话，或直接在本机输入窗里打字；确认文字已经定稿。
4. 按 **`⌘Enter`** 并松开，或点击“发送到远程”。等待约两秒，不要点击、打字、滚动或切换窗口。
5. 在远程窗口检查文字。工具只粘贴，不会替你按回车提交；由于没有远端送达确认，请勿在未检查时反复发送。

| 快捷键 | 作用 |
| --- | --- |
| `⌘L` | 全局打开输入窗；可能占用其他应用的同一快捷键，例如浏览器地址栏 |
| `⌘Enter` | 在输入窗发送文字 |
| `⌘K` | 在输入窗立即清空文字 |

`⌘L` 如果注册失败，菜单会提示快捷键不可用；仍可使用屏幕共享窗口右上方的悬浮按钮。看不到悬浮按钮时，在本工具菜单栏图标的“更多”中选择“3 秒后点击远程输入框”，然后在三秒内点击远程输入框。

**输入窗收起后再次打开会自动清空文字。** 发送失败时当前窗口会显示原因并保留文字，但收起后重新打开仍会清空；需要保留时请先复制。选择备用远程位置的过程中会保留当前文字。

## 常见问题

- **远程没有出现文字**：先看输入窗或菜单栏的失败提示；检查共享剪贴板已开启、辅助功能和自动化权限已授予、远程输入框已点击。发送后等待期间不要操作。检查远程内容后再决定是否重试。
- **提示共享剪贴板未开启**：在苹果屏幕共享的“编辑”菜单中勾选“使用共享的剪贴板”，收起菜单后重试。
- **提示检测到新的点击、按键或滚动**：这是为了避免向错误窗口粘贴而取消。重新点击远程输入框，再次打开输入窗并发送，发送后暂时不要操作。
- **更换应用版本后提示授权**：重新构建或更换签名身份可能需要在系统设置中重新授权。
- **需要排查本机粘贴**：在菜单栏图标的“更多”中选择“本机粘贴自检”。它只验证本机输入框，不验证远程送达。

发送会替换本机剪贴板，不会自动恢复之前复制的内容。应用不保存听写历史或正文日志；豆包的语音处理方式由其自身设置决定。公司策略、网络或远程系统可能限制共享剪贴板；本工具不会绕过这些限制。目前仅针对苹果屏幕共享，不保证支持其他远程软件。

## 从源码构建

需要 macOS 13+、Swift 6 工具链和 Xcode 或相应命令行开发工具：

```sh
swift test
zsh scripts/build.sh
open dist/RemoteVoiceInput.app
```

构建脚本默认优先使用本机 Apple Development 签名身份，否则使用 ad-hoc 签名。可设置 `RVI_SIGN_IDENTITY=-` 明确使用 ad-hoc 签名。构建产物未经过 Apple 公证。

源代码位于 `Sources/`，自动化测试位于 `Tests/`。原理和排障细节见 [排障与验收记录](docs/TROUBLESHOOTING.md)。仓库中的历史实机验收记录针对当时的环境，不能代替在你的设备上检查远程结果。
